# Sistemas Distribuídos

## Por que este tópico é importante?

Quando uma aplicação depende de vários serviços, surgem falhas parciais, latência de rede e consistência eventual. O modelo mental precisa mudar em relação a uma aplicação local.

## O que estudar

- [ ] falhas parciais
- [ ] timeout
- [ ] retry e backoff
- [ ] circuit breaker
- [ ] idempotência
- [ ] consistência eventual
- [ ] CAP — visão crítica
- [ ] replicação
- [ ] particionamento
- [ ] distributed locks
- [ ] sagas
- [ ] transactional outbox

## Exercícios práticos

- [ ] Projetar uma operação que salva no banco e publica um evento sem perder consistência.
- [ ] Descrever o comportamento de um serviço quando uma dependência externa está indisponível.
